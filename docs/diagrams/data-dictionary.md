# Data dictionary

Generated by `python scripts/build_design_pack.py` from the SQLAlchemy tables, the trace models and the request models. Types, keys, nullability, limits and enumerations are read from the code; the meanings are maintained in `scripts/design_pack/data.py`, and the build fails if a column has no meaning. Do not edit by hand.

## 2. Trace document (Granite Trace v1)

The JSON document stored in `runs.trace`. JSON Schema: `packages/granite_core/schema/granite-trace-v1.schema.json`.

### TraceV1

| Field | Type | Meaning |
|---|---|---|
| `schema_version` | `Literal['granite.trace/v1']` | Always `granite.trace/v1` |
| `run` | `RunInfo` | Facts about the whole run |
| `steps` | `list[Step]` | Recorded steps in execution order (at most 500) |

### RunInfo

| Field | Type | Meaning |
|---|---|---|
| `external_id` | `str | None` | Id given by the caller (the API uses the run id) |
| `workflow` | `str` | Workflow key |

| `task_input` | `dict[str, Any]` | The task the workflow was given |
| `final_output` | `dict[str, Any]` | Outputs of the last step; empty if the run errored |

| `ended_at` | `datetime | None` | End of execution |

### Step

| Field | Type | Meaning |
|---|---|---|

| `error` | `str | None` | Why the step failed; null if it succeeded |
| `started_at` | `datetime | None` | Start of the step |
| `ended_at` | `datetime | None` | End of the step |

## 5. Identifiers and hashes

| Item | Format |
|---|---|
| Record ids | a prefix (`run_`, `fnd_`, `hyp_`, `exp_`, `ev_`, `rev_`, `job_`) and 12 hexadecimal characters from a random UUID |
| Step ids | letters, digits, `_` and `-`; unique within a trace |
| Read reference | `step.field` of an earlier step, or `task.field` |
| Trace version | `granite.trace/v1` |
| Evidence and trace hash | SHA-256 of canonical JSON (sorted keys, no extra whitespace, UTF-8) |
| Recorded answer key | SHA-256 of model, messages, parameters and seed |
