# Design pack (Iteration 1)

Generated by `python scripts/build_design_pack.py` from the code. Do not edit by hand: change the code or `scripts/design_pack/`, then rebuild. CI fails if this file is out of date.

21 diagrams and a data dictionary cover every design artefact that handbook Table 1a lists for the FYP-1 mid evaluation. They are drawn by a small generator in `scripts/design_pack/` so that one visual style is used throughout and so that facts come from the code: tables, columns and keys from the database models; states and events from the lifecycle module; steps, reads and checks from the workflow definition; call edges from static analysis of the source; verdict regions and worked examples by calling the real functions on a recorded run. A layout lint rejects overlapping boxes, text that overflows, and connectors through boxes.

**Interactive version:** [`granite_design-pack_fyp1-mid_v1.0.html`](../../deliverables/stage-1-fyp1-mid/granite_design-pack_fyp1-mid_v1.0.html) (one self-contained file: navigation, search, zoom, and click a box to highlight what it connects to).

## How each diagram is kept true to the code

| Diagram | Kept true by |
|---|---|
| [Use-case diagram (Mid-1 scope)](architecture.md) | Curated from the use-case table of the plan; implementation status follows docs/plan/requirements-trace.md. |
| [Layer diagram](architecture.md) | Layout is curated. The dependency rule it shows is enforced mechanically by scripts/check_architecture.py. |
| [Component diagram](architecture.md) | Curated layout. Every arrow from a service to a core component corresponds to an import that the generated call graph shows function by function. |
| [Domain model (class diagram)](architecture.md) | Every field name shown is checked against the real class when the pack is built; a renamed or removed field fails the build. Relationships and layout are curated. |
| [Structure chart](architecture.md) | Curated; the function names are the real ones and are cross-checked by the generated call graph. |
| [Investigation flow](behaviour.md) | Curated. The statuses it names are the states of the generated state machine. |
| [Activity diagram: one investigation](behaviour.md) | Curated. The activities are the modules of the structure chart and the messages of the two sequence diagrams. |
| [Interaction overview diagram](behaviour.md) | Curated; each 'ref' names a sequence diagram of this pack. |
| [Data flow diagram: context (level 0)](behaviour.md) | Curated; the level-1 diagram refines the single process. |
| [Data flow diagram: level 1](behaviour.md) | Curated; process names are the modules of the structure chart and the stores are the tables of the ER diagram. |
| [Finding state machine](finding-state-machine.md) | States, events, targets and levels are read from granite_core.lifecycle when the pack is built. If a transition is added or removed in the code, the build fails until the drawing is updated. |
| [Lineage graph of the Refund Desk](refund-desk-dataflow.md) | Fully generated: steps, edges, field names, checks per step, repair rules and the fault target are read from the workflow definition when the pack is built. |
| [Sequence diagram: run and analyse](verification-sequence.md) | Curated from the code paths; the function names appear in the generated call graph, and the journey is exercised by apps/api/tests/test_journeys.py and tests/system. |
| [Sequence diagram: verify a hypothesis](verification-sequence.md) | Curated from the code paths; the same calls appear in the generated call graph and the flow is covered by packages/granite_core/tests/test_experiment.py. |
| [Call graph (computed from the source)](behaviour.md) | Fully computed: 38 functions and 49 call edges extracted from 19 source files by static analysis every time the pack is built. |
| [Database schema (ER diagram)](database-schema.md) | Tables, columns, types, nullability, keys and foreign keys are read from the SQLAlchemy metadata when the pack is built; a new table, column or foreign key fails the build until the drawing and dictionary are updated. |
| [Check language: from text to result](algorithm-design.md) | Limits, the function list and the example expression are read from the code when the pack is built. |
| [Attribution: ranking where a failure began](algorithm-design.md) | Weights, threshold, decay and the hypothesis limit are read from the module; the worked example and its comparison with ground truth are computed from the recorded run. |
| [Verdict rule VR-1](algorithm-design.md) | Thresholds, limits, every dot and every table cell are computed by calling decide() and wilson() when the pack is built. |
| [Replay plan: fix one step, keep everything before it](algorithm-design.md) | The frozen and re-executed steps come from plan_replay(), the patched field from the workflow's repair rule, and the counts and verdict from run_experiment() on the recorded run. |
| [Deployment diagram](architecture.md) | Curated. Ports, modes and file locations are the defaults in apps/api/granite_api/config.py and the Dockerfile. |
