# deliverables

Frozen records, one folder per evaluation stage. Codes mirror the handbook's stages (Appendix A).

| Folder | Stage | Evaluator |
|---|---|---|
| `stage-0-proposal/` | proposal defense (11 Sep 2026) | panel + supervisor |
| `stage-1-fyp1-mid/` | FYP-1 mid (week 8) | supervisor only |
| `stage-2-fyp1-final/` | FYP-1 final (+ poster) | panel (demo) + supervisor (report) |
| `stage-3-fyp2-mid/` | FYP-2 mid / pre-job-fair, and the job fair | panel + supervisor |
| `stage-4-fyp2-final/` | FYP-2 final and final-deliverables bundle | supervisor |

- These are **exports** of sources kept elsewhere (`docs/report/`, code tags, `research/eval/`). Never edit a submitted file; fix the source and export a new version.
- Names: `granite_<artifact>_<stage>_v<X.Y>.<ext>` when submitted, `..._draft.<ext>` while in progress (see [`workspace-guide.md`](../docs/workspace-guide.md) section 4.3). Stage 0 keeps its original names.
- A stage folder closes when its evaluation is over; later fixes belong to the next stage.
